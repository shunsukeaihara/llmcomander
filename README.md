# LLM Commander

声で指揮するRTSのPoC。発話をLLMが解釈して「作戦」として登録し、作戦ごとの担当LLMが並列で戦況を見ます。ユニットはLLMを待たず、設定された交戦規則で動き続けます。

- コンセプト: [docs/concept.md](docs/concept.md)
- 画面(デモ場面): [docs/screenshot-poc.png](docs/screenshot-poc.png)

## 動かし方

必要なもの: [Godot 4.7(.NET版)](https://godotengine.org/download)、.NET SDK 8 以上、マイク(音声を使う場合)

1. `game/.env.example` を `game/.env` にコピーして、`OPENAI_API_KEY` を書く。司令役・作戦ごとの担当・音声認識をすべて OpenAI で動かすので、キーはこれ1つです(Claude を使う場合は `LLM_PROVIDER=anthropic` と `ANTHROPIC_API_KEY`)。
2. Godot で `game/project.godot` を開き、ビルドして実行する(F5)。

キーがなくてもゲーム自体は動きます(指示は受け付けません)。

### 操作

| 操作 | 内容 |
|---|---|
| Space 長押し | 話す。離すと送信。話しながらクリックした地点は「指示点1, 2…」としてLLMに渡る |
| Enter | 文字で指示する(音声の代わり) |
| 左クリック | 自軍のユニットを選択(「こいつら」「選択中の」で参照できる)。地面なら選択を外す |
| 左ドラッグ | 範囲選択(Shift を押しながらで選択に追加) |
| 右クリック(選択中) | 直接指示: 地面へ移動して待機、敵兵・敵の建物を攻撃(敵兵は見えている限り追う)、村人なら木・金・食で採集、建設中の建物の建設、自軍の村の中心にこもる。兵は作戦「直接指示」にまとまる |
| 1 → クリック | 地点の目印を置く(地点A, B…) |
| 2 → ドラッグ | 線の目印を引く(線A, B…)。「槍は線Aで受け止めて」のように使う |
| 目印・指示点をドラッグ | 動かす(線は端をつかむと端だけ、途中をつかむと線ごと)。その目印を持ち場や行き先にしている部隊もついていく |
| 右クリック(何も選択していないとき) | 目印を消す |
| ミニマップをクリック / ドラッグ | その場所へカメラを移す。話しながらクリックすると「指示点」になる |
| WASD / 矢印 / 画面の端 / 中ドラッグ / ホイール | スクロールとズーム |
| 作戦カードをクリック | その作戦の部隊の場所へ(経済は自軍の基地、予備は集合地点) |
| N / 上部バーの警報をクリック | 直近の警報の場所へ。N を続けて押すと一つ前の警報へ |

画面は、ウィンドウに 1600×900 が何個入るかに応じて整数倍に拡大します(4K なら2倍)。ミニマップは画面の幅に合わせて大きさが変わります。
| Tab | 地図上の意図表示の切り替え |
| C | 右の作戦パネルを折りたたむ・開く |
| F9 | プレイログのフォルダを開く |
| F8 | 霧の切り替え(デバッグ用) |

建設の提案は作戦カードの「OK」ボタンか、「OK」と言うと確定します。

### 指示の例

- 「木に8人、金に3人。村人は作り続けて」
- 「兵舎を基地の近くに」→「OK」
- 「槍と弓を北の丘に。弓は後ろから軍事ユニット優先」
- 「槍は線Aで受け止めて、騎兵は右で待機、槍が接触したら回り込め」
- 「弓は引き撃ち、他は撤退」
- 「斥候で村の中心の周りを同心円状に少しずつ探索して」「敵を探して、見つけたら遠巻きに様子を見て」(偵察任務。行き先は担当のLLMが着くたびに決める)
- 「斥候は食料を見張って、攻撃されたら逃げて」
- 「村人を村の中心に避難させて」(中の人数と同じ本数の矢を撃つ)/「外に出て仕事に戻って」
- 「新兵は北の丘に集めて」

## プレイログ

1試合ごとに、ユーザーデータフォルダの `logs/` に JSONL ファイルが1つ作られます(F9 で開けます。Windows では `%APPDATA%\Godot\app_userdata\LLM Commander\logs`)。記録する内容は次のとおりです。

- 発話ごと: 音声認識の結果と時間、LLMに渡した状況の全文、返ってきた命令とその適用結果、応答時間
- 作戦ごとの担当LLMの呼び出し、条件の発動、警報、ボタン操作、目印の追加と削除
- 30秒ごとの戦況(資源、村人の割り当て、作戦ごとの兵数と規則、敵の兵数、損害)と試合の結果

要約は次のように見ます。

```sh
python tools/playlog/summarize.py ログ.jsonl            # 応答時間の統計、発話と結果の一覧、出来事、戦況の推移
python tools/playlog/summarize.py ログ.jsonl --cmd 3    # 3番目の発話で、LLMに渡した状況と返ってきた命令の全文
python tools/playlog/summarize.py ログ.jsonl --officer  # 担当LLMの報告と調整の一覧
```

解釈がおかしかった試合のログを渡してもらえれば、指示文やツールの直しに使えます。保存先は環境変数 `LLMC_LOG_DIR` で変えられます。

## LLMの応答時間を測る

ゲーム画面なしで、交戦中の場面に用意した発話を流し、司令LLMと担当LLMの応答時間と出力を表示します。

```sh
cd tools/bench
dotnet run                        # 用意した発話を順に流す
dotnet run -- "騎兵で敵の弓を狙え"   # 任意の発話
```

`game/.env` のキーとモデル設定を使います。`COMMANDER_MODEL=gpt-5.5` などに変えて比べられます。

## 構成

| 場所 | 内容 |
|---|---|
| `game/src/Sim` | シミュレーション(マップ、経路探索、経済、戦闘、作戦と交戦規則、敵AI)。Godot に依存しない |
| `game/src/Command` | LLM に渡す状況の要約、ツール定義、ツール呼び出しの適用、非同期の実行管理 |
| `game/src/Llm` | OpenAI(LLM と音声認識)と Claude の呼び出し、設定の読み込み |
| `game/src/View` | 描画、UI、入力、マイク録音 |
| `tests/` | シミュレーションと指揮層のテスト(`dotnet test tests/LlmCommander.Tests`) |
| `tools/sprites` | Blender でユニットのドット絵を作る工程 |
| `tools/bench` | LLM の応答時間の計測 |
| `tools/playlog` | プレイログの要約 |
| `tools/perf` | シミュレーションの重さの計測(`dotnet run -c Release -- 120 --warmup`) |

画面確認用に、`LLMC_DEMO=1` で交戦中の場面から始まり、`LLMC_SCREENSHOT=out.png` で画面を保存して終了します。
`LLMC_DEMO=battle` は両軍が人口上限いっぱいでぶつかる場面で、`LLMC_PERF=1` を付けると描画側の処理時間を5秒ごとに出力します。
